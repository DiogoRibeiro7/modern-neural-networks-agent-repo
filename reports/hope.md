## 1. Claim level

**`research prototype`** — see [`docs/claim_policy.md`](../docs/claim_policy.md).

This is the weakest claim level in the repository and it is the right one. The track
implements the level decomposition the source derives for gradient descent and its
momentum variant, and the self-referential learning rule. It does **not** implement the
Continuum Memory System or the Hope architecture, and **no model here is called Hope**.

## 3. Method

The **formalization audit** is the first deliverable of this track and was written before
any code: [`docs/nested_learning_audit.md`](../docs/nested_learning_audit.md). It derives
the levels, their states, their objectives, and their update frequencies from the source's
equations 1, 8-13 and 58-60, and states which stages of the prompt's development strategy
are implemented and which are declined.

The experiment is a **continual stream**: four unrelated linear tasks presented in order,
with no task boundaries revealed to the learner. The headline metric is mean squared error
across **all** tasks after the whole stream, which measures retention rather than
plasticity.

Learners differ *only* in level structure. Each selects its learning rate from the same
grid on validation, because a two-level learner's effective step is `eta / (1 - decay)` and
a shared rate would compare step sizes rather than level structures.

## 8. Failures and instabilities

**No run diverged in the reported experiments.** All 50 records have `status="success"`.

**Two methodological defects were found and fixed before these numbers were produced.**

*The first was a shared learning rate.* The two-level learner's effective step is
`eta / (1 - decay)` — ten times larger at `decay = 0.9` — so at a common rate it exceeded
the stability threshold and diverged to a loss of `1.4e8`. Reporting that as "momentum is
worse" would have been a step-size comparison dressed up as an architecture comparison.
Every learner now selects its rate from the same grid on validation.

*The second was that the seeds varied nothing.* The learners were deterministic and the
stream was fixed, so all five seeds produced bit-identical runs and every interval had
width exactly zero. That is worse than reporting a single seed, because it looks like
evidence of stability. The L0 state is now randomly initialized per seed.

**A caveat that remains, by construction.** Even now, seed variance covers only
initialization on a *convex* problem, so the intervals are extremely narrow (std ~1e-4 or
below). **They describe reproducibility, not uncertainty about the conclusion.** A proper
uncertainty estimate would resample the stream itself, which is listed as a next
experiment.


## 9. Interpretation

**1. The falsifiable part of the claim holds exactly.** The source argues that gradient
descent with momentum *is* a two-level associative memory. If so, "add a level" and "use
momentum" must be the same edit. They are:
`test_two_level_learner_matches_torch_sgd_with_momentum` asserts that composing L1 with L0
reproduces `torch.optim.SGD(lr=0.05, momentum=0.9)` step for step, and removing L1
reproduces plain gradient descent bitwise. This is the strongest form the claim can take
in code, and it survives.

**2. Adding the second level makes retention worse, not better.** Across all tasks after
the full stream:

| stream | one level | two levels |
|---|---|---|
| continual | **0.806 ± 0.0002** | 1.365 ± 6e-8 |
| conflicting | **0.882 ± 0.0002** | 1.797 ± 5e-8 |

The per-task breakdown shows why, and it is stark. The two-level learner fits the *final*
task perfectly (MSE 0.000) and scores ~1.8 on all earlier ones. A predictor that always
outputs zero scores about 1.0 here. **So momentum does not merely forget earlier tasks; it
is driven past forgetting into actively anti-correlated predictions.** The one-level
learner decays to ~1.0 — it forgets down to the zero predictor and stops there.

**3. But the second level buys plasticity, which is the other half of the trade.** On
few-shot adaptation to a fresh task after a long history, the ordering reverses:
1.076 for two levels against 1.558 for one. This is the classic stability-plasticity
trade-off, and the level framing locates it precisely: the extra level is an accumulator
whose contents *are* a bias toward recent gradients.

**4. The timescale claim is audited, not assumed.** The artefact records each level's
update count: with `period = 4` the gradient memory performs 200 updates while the data
memory performs 800, over 800 samples. A "slower level" is therefore a real, checkable
property of the implementation rather than a description. Making it slower did **not**
help — 1.416 against 1.365 on the continual stream, and 2.371 against 1.797 on the
conflicting one — because a stale gradient estimate is simply a worse one here.

**5. The reset ablation shows nothing, and that is the most informative negative.**
Discarding the momentum state at every task boundary changes the result by less than
`1e-7`. The reason is quantitative rather than conceptual: the gradient memory's horizon is
`1 / (1 - decay) ~ 10` samples, and the tasks are 200 samples long, so by the time a
boundary arrives the state retains nothing from before it. **The source's argument that
"knowledge about the loss landscape lives in the momentum state" is therefore bounded
here: whatever is stored has a ten-sample half-life and cannot survive a task change.**
Testing that argument properly requires a decay whose horizon is comparable to the task
length, which is the first next experiment.

**6. The self-referential rule is exactly gradient descent, as the source says it is.**
The `self-referential` learner reproduces `one-level` to seven decimal places on every
stream, because at the `L2` instance the self-generated value `u_t = f_{W_t}(x_t)` equals
`-grad_y L`. That is a *confirmation* of the source's reframing, not a null result: the
claim was that backpropagation already is a self-referential process, and the equality is
what that claim means operationally. Supplying any other value generator immediately gives
a different learner, which `test_a_different_value_function_changes_the_learner` shows.

**7. What none of this establishes.** The experiment uses a linear model on linear tasks
with two levels. It says nothing about the Continuum Memory System, nothing about Hope,
and nothing about whether more levels help in general. The reframing itself — that
optimizers "are" associative memories — is not the kind of statement this or any
experiment can confirm; what can be tested is whether the decomposition predicts behaviour,
and here it predicted the trade-off in point 3 correctly and the reset result in point 5
incorrectly.


## 10. Limitations

1. **Linear tasks and a linear model.** Every conclusion is about a `d_out x d_in` matrix
   trained by first-order methods. Nothing here transfers to deep networks by default.
2. **Two levels.** The source's framework admits arbitrarily many; this tests one against
   two on one stream.
3. **The Continuum Memory System and Hope are absent**, so the source's headline
   architectural contribution is untested here in any form.
4. **The forgetting curve, the few-shot probe, and the conflicting-task stream are
   single-seed.** Only the aggregate metric carries intervals.
5. **"Knowledge in the momentum state" is tested only through one observable consequence**
   — whether discarding that state changes behaviour — not as a claim about what momentum
   represents.

## 11. Next experiments

1. Vary the momentum decay across the range where its horizon `1 / (1 - decay)` spans from
   far below to far above the task length, which is the axis that would make the
   reset ablation informative.
2. Add a third level (a memory over momentum) and test whether the level table's
   predictions continue to hold.
3. Replace the linear data memory with a deep one, so the "levels" are not all linear.
4. Implement the Continuum Memory System **only after** reading sections 7 and 8 of the
   source, and only if the mapping is unambiguous.
