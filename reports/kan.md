## 1. Claim level

**`educational implementation`** — see [`docs/claim_policy.md`](../docs/claim_policy.md).

The mechanism is implemented from the formulation recorded in the source registry and
verified against hand-computable spline cases. Scale, training recipe, and data differ
materially from the paper, no comparison against the official implementation was run, and
no result here is offered as a reproduction of any published number.

## 3. Method

Each edge carries `phi_ji(x) = w_b[j,i]·silu(x) + sum_p c[j,i,p]·B_p(x)`; nodes sum. The
full formulation, shape table, complexity analysis, and equation-to-code mapping are in
[`src/modern_nn_lab/tracks/kan/README.md`](../src/modern_nn_lab/tracks/kan/README.md).

**Fairness controls.**

1. Every model — KAN, baseline, and ablation — is trained by the *same* loop
   (`experiments/training.py`), with the same optimizer, schedule, batch size, epochs, and
   seeds. No architecture receives bespoke tuning.
2. The MLP baseline's hidden width is searched so its parameter count matches the KAN's.
   At equal *widths* the KAN would hold `G + k + 1 = 9` numbers per edge against the
   MLP's 1.
3. Validation drives in-training evaluation; the test split is scored once, after
   training.
4. Every seed is recorded individually and none is dropped.

## 9. Failures and instabilities

**No run diverged.** All 90 records have `status="success"`.

**A protocol defect was found and corrected before these numbers were produced.** It is
recorded here because it is the most instructive result in this track.

The first version of this suite trained every model at one shared learning rate
(5e-3) for 120 epochs. Under that protocol the reported numbers were:

| | KAN | MLP (matched params) |
|---|---|---|
| `sin-2pix` test MSE | 4.3e-4 | **4.2e-1** |
| `exp-sin-plus-square` test MSE | 1.5e-3 | **7.4e-1** |

which reads as a three-orders-of-magnitude architectural victory. It was not. An MSE of
0.42 on `sin(2πx)` is barely better than predicting the mean: the baseline had not
trained. A direct check confirmed it — the *same* MLP reaches 1.2e-3 at 600 epochs and
lr 2e-2. The shared learning rate happened to suit the KAN and starve the MLP.

The fix is in `experiments/tracks/kan.py:select_learning_rate`: every architecture and
every ablation now searches the *same* learning-rate grid, with the same number of trials
and the same epoch budget, choosing on the **validation** split. Under the corrected
protocol the KAN's advantage on the univariate task falls from ~1000× to ~5×.

The general lesson, which applies to every remaining track: **a headline margin of
several orders of magnitude is far more likely to be a broken baseline than a real
result.**

**Where the KAN is fragile.**

- On `sklearn-diabetes` the KAN's test MSE is **1.07** against standardized targets whose
  variance is 1.0. It is worse than predicting the training mean. With 309 training rows
  and 495 parameters concentrated in spline coefficients, it overfits outright. This is a
  clean negative result and is not qualified away.
- The L1 surrogate monotonically *hurts* on the synthetic tasks (1.08e-4 → 1.24e-4 →
  3.63e-4). On a task with no redundant structure to prune, the penalty only removes
  capacity.
- Grid size 20 is worse than grid size 5 (1.73e-4 vs 1.08e-4) with three times the
  parameters and the highest variance across seeds of any setting in the sweep.

## 10. Interpretation

**1. The synthetic advantage is real but bounded by the noise floor.** Targets carry
Gaussian noise with σ = 0.01, so the irreducible test MSE is ≈ 1e-4. The KAN reaches
1.01e-4 on the univariate task and 1.13e-4 on the compositional one — it is essentially
at the Bayes limit. The matched-parameter MLP is not (5.0e-4 and 6.5e-3). So the honest
statement is not "the KAN is 58× better" but "**the KAN saturates the achievable error on
these tasks at this budget and the MLP does not**". The measured ratio is an artefact of
where the noise floor sits; move the floor and the ratio moves with it.

**2. The advantage tracks compositional structure.** The gap is ~5× on the univariate
task and ~58× on `exp(sin(πx₁) + x₂²)` — a composition of univariate functions, which is
exactly the structure a KAN's edge functions encode. This is the expected direction: the
mechanism is a prior, and it pays where the prior holds.

**3. Learned edge functions are the mechanism, and they are essentially all of it.**
Freezing the spline coefficients at initialization collapses the model to 0.35-0.39 MSE —
*worse than the MLP*, because the frozen random splines inject noise the base branch then
has to fight. Meanwhile removing the residual `SiLU` branch entirely changes nothing
(1.089e-4 vs 1.132e-4, overlapping intervals). Both facts point the same way: on these
tasks the spline carries the function and the residual branch is inert. The residual path
is a training aid, not a source of performance.

**4. Cubic splines matter; fine grids do not.** Dropping to order 1 costs 8× (8.0e-4 vs
1.1e-4); order 2 recovers most of it. Grid size, by contrast, is flat from G=3 to G=10 and
*degrades* at G=20. At this problem size, smoothness of the basis buys more than
resolution — and the cheapest configuration in the sweep (G=3, 105 parameters) is
statistically indistinguishable from the default.

**5. On real tabular data the KAN loses to everything, including a plain MLP.** Ranking on
`sklearn-diabetes`: MLP 0.47 < RF 0.52 < GBDT 0.53 ≪ KAN 1.07. Two things are worth
separating. First, the KAN's failure is an overfitting failure specific to the small-n
regime, not evidence about KANs in general. Second — and this cuts against a common
framing — the *trees also lost to the MLP here*. `sklearn-diabetes` is small and close to
linear, so this is a statement about this dataset, not about tabular learning. The one
claim that is supported: **nothing in these results suggests a KAN is a good default for
small tabular problems.**

**6. Transparency costs about 19× in inference latency.** At a matched parameter count the
KAN forward pass takes 1.42 ms against the MLP's 0.074 ms on the same CPU, because
evaluating the B-spline basis costs `O(k·(G+k))` per input before any contraction happens.
Parameter count and compute are not interchangeable here, which is why both are reported.

## 11. Limitations

1. **No reference comparison.** Nothing here was checked against the authors'
   implementation or the paper's numbers. The claim level reflects that.
2. **Small scale.** Two synthetic 1-D/2-D tasks and one 442-row tabular dataset. Nothing
   here speaks to KAN behaviour at scale, on images, or on sequences.
3. **Surrogate regularizer.** The L1 penalty acts on spline coefficients, not activations
   as in the source, so the sparsity sweep tests *this* penalty, not the paper's.
4. **Grid updates excluded from the reported runs.** Adaptive grids are implemented and
   tested but are not part of the reported training loop, because a KAN-only mid-training
   step would confound the mechanism with a bespoke schedule.
5. **Single hyperparameter setting for the baseline.** The MLP's width is matched to the
   KAN's parameter count, but its depth and activation are fixed. A wider baseline search
   might close or widen gaps.
6. **One test-set evaluation per seed, one dataset per regime.** Confidence intervals over
   five seeds capture initialization and batching variance, not dataset variance.

## 12. Next experiments

1. Turn on adaptive grid updates as a *separately reported* variant, with the update
   schedule as an explicit ablation axis.
2. Test extrapolation directly: train on `[-1, 1]`, evaluate on `[-1.5, 1.5]`, and measure
   how fast the spline branch's contribution decays outside the knot range.
3. Add a depth sweep. All results here use a single hidden layer; the compositional
   advantage should depend on depth if it is real.
4. Implement the activation-based L1 plus entropy penalty from the source and compare it
   against the coefficient surrogate used here.
5. Add a tabular dataset where the generating process is genuinely compositional, to
   separate "KAN loses on tabular data" from "KAN loses when the compositional prior does
   not hold".
