## 3. Method

Full detail is in
[`src/modern_nn_lab/tracks/pfn/README.md`](../src/modern_nn_lab/tracks/pfn/README.md).

A conventional model is fitted to a dataset. A PFN is fitted to a *distribution over
datasets* — a prior — once, and thereafter answers a new dataset by reading it as context
in a single forward pass, with no gradient step.

Two structural properties make that well posed, and both are asserted in
[`tests/test_pfn.py`](../tests/test_pfn.py) rather than assumed:

1. **Queries cannot attend to each other.** Each query reads the context and itself. Without
   this the model would be doing transduction over the whole test set, and a prediction
   would depend on which other questions happened to be asked alongside it.
2. **There is no positional encoding.** Permuting the context leaves predictions unchanged.
   A dataset is a set; sensitivity to row order would be an artefact.

A third property is asserted for the same reason: `predict_proba` moves no parameter.

**What is held equal.** Every model sees identical context rows and is scored on identical
queries. The PFN is prior-fitted once on `linear` and then never touched; each baseline is
fitted from scratch on each task's context, which is the normal way those models are used.

**What is deliberately not held equal.** Parameter counts. A prior-fitted transformer and a
per-task logistic regression have no comparable notion of capacity, and matching a number
that means different things in each case would be a worse distortion than stating the
mismatch. The asymmetry in *when* training cost is paid is measured directly in §8.

## 4. Experiment configuration

| Setting | Value |
|---|---|
| Seeds | 0-4 |
| Prior fitting | 600 steps, 16 tasks/step, AdamW 3e-4, grad-norm clip 1.0 |

| Evaluation | 100 tasks per point, 20 queries per task |

| Out-of-prior | `mlp` (random two-layer network), `xor` (parity: no linear boundary works) |

| Label noise | 0.1, applied to context *and* queries |

`gradient_boosting` stands in for the prompt's "CatBoost or another strong GBDT": CatBoost
is not a dependency of this repository, and scikit-learn's boosting is the same family.

TabPFN 8.2.0 gates its checkpoint download behind an interactive browser license
acceptance (`ensure_license_accepted` → `try_browser_login`), which cannot complete in a
non-interactive environment; the attempt fails at the socket layer. Circumventing a license
gate was not an option, so deliverable B is **written but not executed**:
[`reference.py`](../src/modern_nn_lab/tracks/pfn/reference.py) contains the adapter, the
optional `tabpfn` extra is declared in `pyproject.toml`, and
`build_tabpfn_classifier` attaches the pre-training disclosure to the estimator so it
travels with the record rather than living only in prose.

The package was installed once to establish that this was a license gate rather than a
packaging error, then uninstalled to leave the environment as it was found.

**The acceptance criterion this track was given** — never compare the pre-trained
checkpoint with a from-scratch neural baseline without discussing pre-training compute and
data advantages — is satisfied vacuously here, because no such comparison exists. If you
run the adapter locally, it stops being vacuous, and the disclosure above is the text that
must accompany the table.

## 10. Interpretation

**The PFN matches its per-task baselines; it does not beat them.** In prior it scores 0.884,
identical to logistic regression and below the per-task MLP's 0.897. That is the headline,
and it is a smaller claim than the mechanism invites. What it does win on is calibration
(ECE 0.020, the best in the table) and cost (§8) — not accuracy.

**Being out of prior was not, by itself, fatal.** This is where the results contradict what
one would predict from the mechanism. On `mlp` — curved boundaries the model was never
fitted to — the PFN scores 0.836, tying the best baseline, with the best calibration in the
table. A linear prior evidently transfers to that family, which makes sense on inspection:
`mlp` labels come from thresholding a random tanh network at its median, and such a
boundary is often locally close to linear. It is out of prior by construction but not by
much.

**`xor` is the real failure, and it is a calibration failure first.** Accuracy falls to
0.607 — below the per-task MLP's 0.699 — while expected calibration error rises from 0.020
in prior to 0.227, an order of magnitude. The transfer matrix is starker still: a model
fitted on `mlp` and evaluated on `xor` scores **0.430, below chance**, at ECE 0.329. Below
chance is not ignorance; it is a systematically anti-correlated prediction made confidently.
That is the shape of the risk. There is no per-dataset gradient step, so the prior is not a
soft preference that data can overcome — it is the whole hypothesis space, and when it
excludes the truth the model does not become uncertain, it becomes wrong with conviction.

So the two families answer different questions. `mlp` shows that "out of prior" is a matter
of degree, and mild misspecification costs little. `xor` shows what happens at the other
end, where the prior cannot express the target at all.

**The small-n result is the cleanest positive finding.** At n=10 the PFN is the best model
in the table (0.831 against the MLP's 0.825); by n=40 the per-task models have overtaken it
(0.921 against logistic's 0.931). The advantage is real, modest, and concentrated exactly
where per-dataset fitting has least to work with — which is the regime the approach is
usually argued for.

**The economics are the strongest part of the case.** Prediction costs 0.20 ms per dataset
against 2.78-134 ms for a per-task fit, and the 10.6 s of prior fitting is repaid after 79
datasets against the MLP baseline. That cost is paid once, before any of these datasets
existed. It is a genuinely different arrangement from per-dataset fitting, and it survives
the failure modes above in a way the accuracy numbers do not.

**Do not read the d=16 column as an architectural finding.** The prior-fitting budget was
held at 600 steps while the problem got substantially harder, so the drop to 0.669 confounds
misspecification with under-training. It is reported because omitting it would be worse, but
it does not support a conclusion.

## 11. Limitations

- **The prior is synthetic and known.** Every evaluation task here comes from a
  distribution this repository wrote. Real tabular data is not drawn from it, and nothing
  in §5 transfers to real data without evidence that is not collected here.
- **Binary classification, continuous features only.** No regression head, no categorical
  features, no more than two classes.
- **Missingness is imputed, not modelled.** See §7; the mechanism is missing-completely-at-
  random, and no model here handles missing values natively.
- **The feature-count sweep confounds three things**, and supports no conclusion. A wider
  input is a harder problem, a differently-sized model (the input projection grows), *and*
  an unchanged 600-step fitting budget spent on both. See §10.
- **`mlp` is a weak out-of-prior test.** It was chosen as one and did not behave like one
  (§10). Only `xor` exercises genuine misspecification here, so the out-of-prior evidence
  in this track rests on a single family.
- **Cost figures are order-of-magnitude.** Single seed, CPU, on a shared machine.
- **No official checkpoint.** See §9. Nothing in this report bears on TabPFN's quality.
- **Single fitting budget.** 600 steps was not tuned; a longer-fitted PFN might do better
  in prior and would not do better out of it.

## 12. Next experiments

1. Find a family that is *mildly* misspecified and one that is severely so, on a controlled
   axis rather than by construction — §10 shows that `mlp` and `xor` differ in degree, and
   the interesting question is where between them confidence starts to decouple from
   accuracy.
2. Sweep context size on `xor`. §10 argues the prior is the whole hypothesis space, which
   predicts that more context will not rescue it; that prediction is untested here.
3. Re-run the feature-count sweep with the fitting budget scaled to the input width, which
   is the only way to separate the three confounded effects noted in §11.
4. Add a real tabular dataset (OpenML) as a distribution-shift endpoint, with the shift
   from synthetic prior to real data stated as the manipulated variable.
5. Run the adapter in §9 on a machine where the license has been accepted, with the
   disclosure attached, and report it as a *reference integration* rather than a comparison.
